# 决策记录

## D001 · 自研独立客户端，不 Fork 官方 GPL 仓库

**日期**：2026-10-08
**背景**：官方 `MicYou-Dev/MicYou-iOS` 为 GPL-3.0。Timmy 希望加入灵动岛等功能，并考虑变现。
**决策**：不基于官方仓库修改，改为只读研究协议后用 Swift 独立重写。
**理由**：
- 直接改 GPL 代码 + 闭源分发不合规。
- "付费解锁高级功能"在 GPL 下不成立（用户可获取源码并移除付费墙）。
- 协议是自包含的，独立重写成本低。
- 协议接口不受版权保护，独立实现干净。

## D002 · 变现方式采用纯打赏，不做 Paywall

**日期**：2026-10-08
**背景**：原考虑"App 免费 + 高级功能 IAP 解锁（6 元 / 18 元档）"。
**决策**：放弃付费解锁，改为纯打赏（Apple IAP 消耗型 tip）。
**理由**：
- 项目全开源，付费墙与开源定位矛盾。
- 打赏在任何许可证下都合法，不需要独占权。
- 避开 GPL 与 App Review 的双重风险。
- **Apple 官方指南 3.1.1 明文允许**："Apps may use in-app purchase currencies to enable customers to 'tip' the developer."（打赏必须走 IAP，但不能换取数字内容。）

## D003 · 上游源码仅作本地参考，排除出版本控制

**日期**：2026-10-08
**决策**：`MicYou-iOS/` 写入 `.gitignore`，不提交到本项目仓库。
**理由**：避免把 GPL 代码混入自有仓库，保持仓库许可边界清晰。

## D004 · 协议基线改用真实桌面端协议（推翻初版）

**日期**：2026-10-08
**背景**：初版 `PROTOCOL.md` 基于官方 iOS 脚手架的 `Protocol.m` 整理（magic `0x694F5354`/端口 8900/16 字节头/裸 PCM）。
**发现**：与 MicYou **主仓库**交叉核验后确认该协议**与真实桌面端不互通**：
- 主仓库用 `0x4D696359`（"MicY"）+ 8 字节头 + **Protobuf**；
- 握手字符串 `MicYouCheck1`/`MicYouCheck2`；
- 默认端口 `8554`（UDP 8555），mDNS `_micyou._tcp.local.`；
- 支持 PCM 与 **Opus**。
- 全主仓库搜不到 `0x694F5354` 或 `8900`，即脚手架协议在真实实现中不存在。
**决策**：以主仓库 Rust/Android 实现为唯一协议基线，重写 `PROTOCOL.md`（已 commit `6b83ffd`）。
**影响**：
- 写 Swift 客户端必须实现**真实协议**，否则连不上桌面端。
- 复杂度高于初版估计（需 Protobuf + 可选 Opus + 握手串），但仍然可做。
- 官方 iOS 脚手架疑似不能与真实桌面端互通 → **iOS 生态实际上是空的**，机会窗口比预想更大，但也说明这条路没人验证过。

## D005 · 暂不做桌面端 Fork 与原生重写

**日期**：2026-10-08
**背景**：Timmy 提出 Fork 项目并在 Mac / Windows 用原生框架重写一遍。
**分析**：
- 许可证上**可行**：Fork 桌面端属 GPL 衍生作品，只要继续以 GPL-3.0 开源即可；打赏模式与 GPL 兼容。
- 工程上**代价极大**：桌面端需重实现 TCP/UDP 传输、Protobuf、Opus、FEC、抖动缓冲、完整 DSP 链（降噪/AEC/去混响/EQ/AGC/VAD）、Native+WASM 双运行时插件宿主，以及虚拟音频设备集成（Windows 侧接近需签名内核驱动）。
- **且非必要**：现有 MicYou 桌面端已在 Windows/macOS/Linux 可用，iOS 客户端直接对接即可。
**决策**：先只做 iOS 客户端（Phase 1）。桌面端重写列为可选后续，仅在出现明确理由时再评估。
