# 许可说明

> 面向 Timmy 与所有在本仓库工作的 AI agent。
> 本文回答一件事：**每个组件用什么许可**。
> 概念解释用大白话，法律条款用准确表述。

---

## 1. 一句话结论

| 组件 | 许可 | 能不能上 App Store |
|---|---|---|
| **桌面端**（macOS + Windows） | **GPL-3.0**（被迫，因为打包上游二进制） | 不上架（走 GitHub Release），所以无冲突 |
| **iOS / iPadOS 端** | **MIT**（推荐） | ✅ 干净 |

**并且必须记住两件彼此独立的事：**

- **改名**解决的是**商标**问题（能不能用别人的名字）
- **许可**决定的是**版权**问题（能不能收费、要不要开源）

**改名不改变许可义务，许可也不影响商标规则。**

---

## 2. 两个许可证是什么

### GPL（GNU General Public License）

软件默认有主人。没有许可证，你什么都不能做（不能复制、改、分发）。作者给的许可证就是"我允许你做什么"。

**GPL 给你什么**：免费使用、随便改、自由分发、**甚至能卖钱**。

**GPL 的条件（只有一条，但关键）**：

> 你改了它、或把它拼进自己的程序里分发出去 → **你的整个程序也必须用 GPL 发布**。
> 也就是：必须公开源码，且接收者享有同样自由。

**它禁止的两件事**：① 收钱了不给源码；② 给使用者附加任何额外限制（GPLv3 §10）。

**比喻**：GPL 是一本**共享菜谱**。你可以照着做菜、改配方、拿去卖，**但必须把改后的配方一起给买家**，买家也能继续改、继续传。所以你没法靠"只有我知道配方"赚钱。

外号 **copyleft**（"反向版权"）：用版权的手段保证自由不被吃掉。

### MIT

出自麻省理工学院，最宽松、最常用的开源许可证之一。

**给你什么**：几乎一切自由——用、改、卖钱、闭源、再许可。

**要你什么**（只有两条）：

1. **保留署名**：保留原作者的版权声明与许可证文本
2. **免责**：作者不为使用后果负责

**关键：MIT 没有传染性。** 你把它拼进自己的程序，**你的程序不必跟着开源**——想闭源就闭源，想收费就收费。

**比喻**：MIT 是**免费样品**。随便你拿去用、做菜卖钱；唯一要求是别声称是你原创的。

## 3. 对比

| | **GPL-3.0** | **MIT** |
|---|---|---|
| 免费用、随便改 | ✅ | ✅ |
| 能卖钱（法律上） | ✅ | ✅ |
| **你自己的程序必须开源** | **必须** | **不必** |
| **能否闭源** | ❌ | ✅ |
| **能否上 App Store** | ⚠️ 存在冲突（见第 5 节） | ✅ 干净 |
| 附加限制（DRM 等） | 禁止 | 允许 |
| 条件 | 传染性开源 + 不加限制 | 保留署名 + 免责 |

## 4. 本项目的许可决定（分组件，不要混为一谈）

### 桌面端 → **GPL-3.0（无选择余地）**

采用路线 B：原生 UI + **打包上游 `micyou-cli` 二进制**。上游是 GPL-3.0，因此我们的分发必须遵守 GPL：

- 整体以 GPL-3.0 授权（§5c）
- 保留上游版权与许可声明（§5b）
- 修改上游源码（如给 CLI 加 JSONL 通道）须标注修改与日期（§5a）
- 界面显示 Appropriate Legal Notices（§5d）
- 提供完整对应源码（§6）

**桌面端不上 App Store**（走 GitHub Release 分发），所以第 5 节的冲突不存在。

### iOS / iPadOS 端 → **MIT（推荐，非强制）**

iOS 端是**独立实现协议**（未复制上游代码），因此是**我们自己的作品**，**不受 GPL 约束**，可自选许可。

**强烈建议用 MIT，而不是 GPL**，原因见第 5 节。

**技术前提**：必须确保它是真正的独立实现——只参考协议事实（magic、端口、字段号、握手串），**不复制上游任何源码或 `.proto` 文件**。协议接口本身不受版权保护。

## 5. 为什么 iOS 端不能用 GPL：App Store 的冲突

**GPL 说**：不得给使用者附加任何额外限制（§10）。

**Apple App Store 说**：

- 下载的 App 有 **DRM（FairPlay 加密）**，用户不能自由复制给别人
- 安装设备数受限，Apple 可远程撤销
- iOS 上不能像安卓那样自由分发

**两者直接矛盾**：一个要求"完全自由"，一个附加"多项限制"。

**这不是理论**，有真实先例：

- **2011 年 VLC 的 iOS 版被开发者主动从 App Store 撤下**，原因即 GPL 与 App Store 条款冲突
- **2010 年 GNU Go** 因同样原因下架

**实际后果**：平时可能没人管；**一旦有人投诉，Apple 会直接下架**。这是一颗长期悬着的雷。

> 说明：这属于**有争议的法律领域**（FSF 认为冲突，Apple 不认同），不是已判定的铁案。但风险真实存在，能让开就让开。

**因此**：iOS 端要用 GPL 就等于主动引入这个风险。用 MIT 则**完全不涉及**。

## 6. 给 AI agent 的硬性规则

1. **桌面端**（`apps/`、`core/`）：**GPL-3.0**。必须保留上游版权声明、完整许可文本、并标注 GPLv3 §5 要求的修改与日期。
2. **iOS / iPadOS 端**（`Sources/`、`Tests/`、Xcode 工程）：**MIT**。**不得**标为 GPL，否则引入 App Store 冲突风险。
3. **跨线共享的 Swift 协议核心**（`Sources/MicWispCore`）：属 iOS 线，**MIT**。
4. **任何组件都不得删除原作者版权声明。**
5. **不得**把上游 GPL 源码（`.rs` / `.kt` / `.m` / `.swift` / `.proto`）复制进本项目。
   协议事实可自由实现；**表达**不可复制。
6. **不得**把产品名写成 `MicYou`，不得使用其 logo/字体/配色（商标问题，见 `AGENTS.md`）。
7. 若某个新组件或新依赖引入许可冲突（例如引入 GPL 库到 MIT 部分），**先停下报告，不要自行决定**。

## 7. 附：商标 vs 版权（常见混淆）

| | 商标 | 版权 / 许可 |
|---|---|---|
| 管什么 | **名字、logo** 能不能用 | 代码能不能复制、修改、分发 |
| 来源 | 使用（注册+使用，或先用） | 作者的许可证 |
| GPL 是否授权 | **完全不授权**（GPLv3 §7e 明确允许附加"不授予商标权"条款） | 授权 |
| 本项目的应对 | 换名 `MicWisp`；可描述"兼容 MicYou 协议"；不得暗示官方 | 桌面 GPL、iOS MIT |

**改名解决商标，不改许可；两者互不影响。**
