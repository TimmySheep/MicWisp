# 完整客户端范围与验收清单

本文件把当前授权目标拆成可验收功能。产品名为 MicWisp；上游 `MicYou-iOS/` 仅用于确认功能意图；本项目必须使用独立 Swift 实现，并以真实桌面端协议 `PROTOCOL.md` 为准。用户可见功能参考自上游 `v2`（本地参考 commit `9ee4ea1`），不代表其旧网络协议兼容真实服务端。

## 实施计划

1. **协议基线**：依赖零引入的 Protobuf/帧编解码、畸形包校验及单元测试。
2. **可运行客户端**：Xcode App + Live Activity targets、原生界面、设置持久化、mDNS 与 TCP 握手/心跳/PCM 传输。
3. **音频完整性**：系统音频路由、后台/中断恢复、静音、格式协商与错误恢复；接入 RNNoise / Opus 前先完成依赖与许可核查。
4. **功能补齐**：可视化、外观/背景、本地化、通知、日志导出、更新源与开源声明。
5. **验收与发行**：Simulator 构建/测试；真实桌面端及 iPhone 实测；最后补应用图标、发行元数据与签名。发行配置依赖用户的真实服务端、设备、账号和发布决定。

**当前阶段**：第 1 阶段已初步完成并通过 8 项本地测试；第 2 阶段进行中。后续阶段依赖每阶段回归验收，不将计划误报为已完成。

## 协议与连接

- [ ] 手动输入主机 / 端口、校验并记住最近连接

- [ ] TCP `MicYouCheck1/2` 握手、Connect、8 字节帧、Protobuf 编解码

## 验收层级

1. 协议核心：无外部依赖的单元测试覆盖字节序、Protobuf、流式分帧、畸形输入与大小上限。
2. 工程：可在本地 Xcode / iOS Simulator 编译；资源、扩展、隐私声明均进入构建。
3. 端到端：连接真实 MicYou 桌面端，验证发现、握手、音频、心跳、静音、断线恢复；需实机验证麦克风、后台和 Live Activity。
4. 发行：配置真实 bundle ID、图标与 App Store Connect 元数据后，才可称为可发布产品。

## Apple Watch 客户端（第三条工作线）

用户确认要实现 **Apple Watch 伴侣 App** 的以下功能（**7 项，全部要做**）：

1. **W-1 远程麦克风开关** —— 手表切换 iPhone 端麦克风
2. **W-2 连接状态显示** —— iPhone ↔ 上游机器状态、机器名、已持续时长
3. **W-3 表盘复杂功能** —— 状态放表盘 / Smart Stack，抬腕即见
4. **W-4 震动确认** —— 操作成功 / 失败的手腕反馈（成功与失败可区分）
5. **W-5 断连震动告警** —— 与上游断开或延迟飙升时震手腕
6. **W-6 静音提醒（绝不自动恢复）** —— 静音中周期性轻震提醒你仍在静音
7. **W-7 数码表冠调增益** —— Digital Crown 调输入增益（依赖上游控制通道补丁）

> ⚠️ **安全红线：禁止任何自动改变麦克风状态的行为。**
> 用户已明确否决"静音定时自动恢复"——自动恢复会在**用户不知情时打开麦克风**，
> 构成隐私风险。W-6 只能是**提醒**，是否恢复必须由用户显式操作。

> **完整设计、消息契约、通道选择、生命周期坑与验收标准见
> `docs/WATCH-SCOPE.md`（必读，不要自行改设计）。**

要点速览：

- 手表**不直连**上游机器（watchOS 网络限制 + 麦克风在 iPhone 上），
  只经 `WCSession` 与 iPhone 通信
- **watch → iPhone 用 `sendMessage`**：Apple 文档明确 iPhone app **永远可达**，
  从手表调用会唤醒后台的 iOS app → **静音指令可靠**
- **iPhone → watch 用 `updateApplicationContext`**：手表仅在前台才可达，
  状态用「最新快照」语义
- 消息契约必须**版本化**（`v` 字段），两侧共用一份类型定义
- `WCSession.isSupported()` 在 **iPad 上返回 `false`** → 通用 App **必须先判断**，
  否则 iPad 上崩溃
- ⚠️ **模拟器不能复现后台/唤醒行为** → 静音与后台唤醒**必须真机验证**；
  无法真机就**如实标注「未真机验证」**，不得写成通过
- 命名统一 `MicWispWatch`；许可 **MIT**（**不得标 GPL**）
- **7 项功能全部要实现**；按**依赖**分三批：无依赖的先做（W-1 / W-2 / W-4 / W-6），
  再做 W-3 / W-5；**W-7 必须等上游控制通道补丁**（未就绪时 UI 预留为隐藏 / 禁用，
  **绝不用假数据假装可用**）

**实施顺序**：先完成进行中的改名与 iPad 适配，**再做 Apple Watch**。
